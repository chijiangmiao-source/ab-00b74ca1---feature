# 静默跳转故障规程 · 弱互模拟审计

卫星地面站故障规程复核工具：工程师在页面录入两份含静默内部跳转（`tau`）的
有限状态规程（状态、初始状态、迁移），系统判定两个初始状态是否维持相同的
**可观察承诺**（弱互模拟 / weak bisimulation），并可切换 **分支保持复核**
（branching bisimulation）：确认一方执行可观察动作前穿越的静默步骤不会悄然丢失
另一方仍可观察的分支承诺。

- 仅以 `tau` 静默跳转（含静默环、状态重命名）造成的差异 → 判定**等价**，
  最终关系对称呈现，包含两个初始状态对 `(s0, t0)` 与 `(t0, s0)`。
- 一侧的可观察动作不能由另一侧以“静默前缀后承接同动作”承接 → 判定**不等价**。
- 审查员可展开**首个淘汰状态对、挑战动作与按轮次递减的依据**；每项失败义务
  仅引用更早轮次的淘汰结果，状态对、动作、候选响应全部稳定排序，支持自底向上复算。
- **分支保持复核**模式下，结果与普通弱互模拟并列显示；分支保持失败时可展开
  首个淘汰状态对、挑战动作、**静默前缀候选及其同轮关系违约**（候选按落点状态、
  前缀长度、前缀序列稳定排序）。切回普通模式或修改任一规程后，旧分支保持结论
  与依据立即清除；普通弱互模拟接口与结论不变。
- 每份规程最多 **18 个状态**、**4 种可观察 ASCII 动作**与 1 种 `tau` 动作；
  状态名与迁移标识唯一。迁移端点、初始状态或动作集合无效时，**一次显示所有问题
  并清除旧结论**。

## 弱转移与判定

- `s ==tau=> p` 当且仅当 `s` 经任意条（含 0 条）`tau` 到达 `p`；
- `s ==a==> p`（`a` 可观察）当且仅当存在 `u`：`s` 经静默前缀到达 `u`，且 `u --a--> p`；
- 从全集关系 `R₀`（全部跨侧状态对）起逐轮淘汰：第 k 轮以上一轮存活集 `R_{k-1}`
  检查每个存活对双向义务；无存活候选响应的对在本轮淘汰，直到不动点。
  初始状态对在最终关系中即等价。失败义务引用的落点对必然在严格更早轮次淘汰。

## 分支保持判定

与弱互模拟同一套 `R₀` 起逐轮淘汰骨架，区别仅在义务检查：挑战只针对**强迁移**
（`tau` 不再展开为整个静默闭包），应答允许经过静默前缀后承接同一动作，但
静默前缀中的对应状态对必须**仍留在上一轮存活集（同一轮关系）**中：

- 挑战转移 `x --a--> x'`（含 `tau`）由应答状态 `y` 承接，当且仅当存在静默路径
  `y = w0 =tau=> ... =tau=> wn`，随后 `wn --a--> z`（`tau` 挑战时 `z = wn`），且
  每个前缀内部状态 `wi` 与挑战源 `x` 的配对、落点配对 `(x', z)` 均仍存活；
- `tau` 挑战允许零步静默（留在 `y`），其最终落点不要求自身是存活中间状态；
  可见动作的承接点必须仍与挑战源相关。
- 经典静默分叉 `A = tau.a + b` 与 `B = tau.a + a + b`：**弱互模拟等价**
  （B 的直接 `a` 可由 A 经静默前缀承接），但**分支保持不等价**——该静默前缀
  穿越的状态已丢失 `b` 承诺，与 B 初态不在同一轮关系中。页面“静默分叉”示例即此例。

## 本地运行（需 Node.js ≥ 20，零依赖）

```bash
npm test                 # 代码测试
npm start                # 启动服务，默认 :8080
PORT=9000 npm start      # 自定义端口
```

- 页面：`GET /`（右上角切换“普通弱互模拟 / 分支保持复核”）
- 健康路径：`GET /healthz`
- 审计接口：`POST /api/audit`，请求体 `{ "procA": {...}, "procB": {...} }`
- 分支保持审计：`POST /api/audit?mode=branching`，响应在普通结论字段外另带
  `"mode": "branching"`，并在 `weak` 字段内嵌同输入的普通弱互模拟结论；
  失败义务的候选位于 `transitions[].candidates[]`（`prefix` / `action` /
  `target` / `ok` / `violations`）。
- 内置示例：`GET /api/samples`（含静默分叉示例 `branching`）

规程 JSON 形式：

```json
{
  "states": [{ "name": "S0" }, { "name": "S1" }],
  "initial": "S0",
  "transitions": [
    { "id": "t1", "from": "S0", "action": "tau", "to": "S0" },
    { "id": "t2", "from": "S0", "action": "x", "to": "S1" }
  ]
}
```

## Docker / Compose

```bash
docker compose up --build -d          # 在可配置宿主机端口暴露页面
HOST_PORT=9090 docker compose up -d   # 自定义宿主机端口
curl http://localhost:8080/healthz
```

`docker-compose.yml` 提供可执行的 `verify` 服务：等待 `web` 健康后，执行

1. 构建检查（全部源码 `node --check`）；
2. 代码测试（`node --test`）；
3. 接口 / HTTP 冒烟（健康路径、页面、审计接口：
   静默环等价规程必须判等价且含两个初始状态对；
   缺失匹配动作规程必须判不等价；无效输入必须一次返回全部问题并清除旧结论；
   **静默分叉规程普通模式必须判等价、`?mode=branching` 必须判不等价并给出
   首个淘汰状态对、挑战动作、静默前缀候选及其同轮关系违约**）。

```bash
docker compose build
docker compose run --rm verify        # 完成后退出，退出码报告结果（0 成功）
echo $?
```
