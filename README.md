# 静默跳转故障规程 · 弱互模拟 / 分支保持审计

卫星地面站故障规程复核工具：工程师在页面录入两份含静默内部跳转（`tau`）的
有限状态规程（状态、初始状态、迁移），系统判定两个初始状态是否维持相同的
**可观察承诺**（弱互模拟 / weak bisimulation），并可切换 **“分支保持”复核**
（branching bisimulation）确认一方执行可观察动作前穿越的静默步骤不会悄然丢失
另一方仍可观察的分支承诺。

- 仅以 `tau` 静默跳转（含静默环、状态重命名）造成的差异 → 普通弱互模拟判定**等价**，
  最终关系对称呈现，包含两个初始状态对 `(s0, t0)` 与 `(t0, s0)`。
- 一侧的可观察动作不能由另一侧以“静默前缀后承接同动作”承接 → 判定**不等价**。
- 审查员可展开**首个淘汰状态对、挑战动作与按轮次递减的依据**；每项失败义务
  仅引用更早轮次的淘汰结果，状态对、动作、候选响应全部稳定排序，支持自底向上复算。
- **分支保持复核**与普通弱互模拟并列显示：候选响应可经静默前缀，但前缀途中每个
  应答状态与“挑战发起状态”的对应状态对必须仍留在同一轮关系中，随后再承接同一
  可观察动作（`tau` 挑战允许应答方原地不动承接）。存在“弱互模拟等价、但分支保持
  不等价”的静默分叉案例（内置 `branching` 示例）。
- 分支保持失败时可展开首个淘汰状态对、挑战动作、全部静默前缀候选及其违约节点：
  更早轮次淘汰（拒绝锚点，附轮次）、本轮同批淘汰（**同轮关系违约**）、本轮仍存活
  但更晚轮次淘汰（信息性）、最终存活；按状态、动作和候选稳定排序。
- 切回普通模式或修改任一规程后，旧分支保持结论与依据立即清除；普通审计接口
  （不带 `mode`）的响应结构与结论不随分支保持功能改变。
- 每份规程最多 **18 个状态**、**4 种可观察 ASCII 动作**与 1 种 `tau` 动作；
  状态名与迁移标识唯一。迁移端点、初始状态或动作集合无效时，**一次显示所有问题
  并清除旧结论**（两种模式共用同一套输入约束）。

## 弱转移与判定

- `s ==tau=> p` 当且仅当 `s` 经任意条（含 0 条）`tau` 到达 `p`；
- `s ==a==> p`（`a` 可观察）当且仅当存在 `u`：`s` 经静默前缀到达 `u`，且 `u --a--> p`；
- 从全集关系 `R₀`（全部跨侧状态对）起逐轮淘汰：第 k 轮以上一轮存活集 `R_{k-1}`
  检查每个存活对双向义务；无存活候选响应的对在本轮淘汰，直到不动点。
  初始状态对在最终关系中即等价。失败义务引用的落点对必然在严格更早轮次淘汰。

### 分支保持复核（branching bisimulation）

与普通弱互模拟的关键区别在于静默前缀**途中**不可悄然改变承诺。对挑战强迁移
`p --a--> p'`，应答方路径

```
q = q0 =tau=> q1 =tau=> … =tau=> qn --a--> qf
```

仅在下列每个状态对都仍在本轮关系中时才成立：

- 前缀状态对 `(p, q_i)`（每个静默中途状态仍与**挑战发起状态** `p` 配对）；
- 落点对 `(p', qf)`。

`p --tau--> p'` 的静默挑战额外允许应答方**原地不动**承接（只需 `(p', q)` 仍在
关系中）。判定仍在“既有弱互模拟输入约束”内逐轮淘汰：第 k 轮依据 `R_{k-1}`
同步确定本轮淘汰集，故被拒候选必含严格更早轮次淘汰锚点；与本对同批淘汰的
前缀/落点节点标为同轮关系违约。分支保持关系是弱互模拟关系的子集：分支保持
等价蕴含弱互模拟等价，反之不然（见内置 `branching` 静默分叉示例）。

## 本地运行（需 Node.js ≥ 20，零依赖）

```bash
npm test                 # 代码测试
npm start                # 启动服务，默认 :8080
PORT=9000 npm start      # 自定义端口
```

- 页面：`GET /`
- 健康路径：`GET /healthz`
- 审计接口：`POST /api/audit`，请求体 `{ "procA": {...}, "procB": {...} }`
- 分支保持复核：同一接口，请求体增加 `"mode": "branching"`；缺省或其他取值
  均走原有普通弱互模拟（普通响应不含 `mode` 字段）。
- 内置示例：`GET /api/samples`（`equivalent` / `missing` / `cascade` / `branching`）

规程 JSON 形式：

```json
{
  "states": [{ "name": "S0" }, { "name": "S1" }],
  "initial": "S0",
  "transitions": [
    { "id": "t1", "from": "S0", "action": "tau", "to": "S0" },
    { "id": "t2", "from": "S0", "action": "x", "to": "S1" }
  ]
}
```

## Docker / Compose

```bash
docker compose up --build -d          # 在可配置宿主机端口暴露页面
HOST_PORT=9090 docker compose up -d   # 自定义宿主机端口
curl http://localhost:8080/healthz
```

`docker-compose.yml` 提供可执行的 `verify` 服务：等待 `web` 健康后，执行

1. 构建检查（全部源码 `node --check`）；
2. 代码测试（`node --test`，含分支保持算法、证据排序与同轮违约测试）；
3. 接口 / HTTP 冒烟（健康路径、页面、审计接口：
   静默环等价规程必须判等价且含两个初始状态对；
   缺失匹配动作规程必须判不等价；无效输入必须一次返回全部问题并清除旧结论；
   静默分叉规程普通模式必须判等价、`mode: "branching"` 必须判不等价，
   且初始对静默前缀候选引用更早轮次淘汰对、证据含同轮关系违约标注）。

```bash
docker compose build
docker compose run --rm verify        # 完成后退出，退出码报告结果（0 成功）
echo $?
```
